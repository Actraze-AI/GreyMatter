# 3D Brain Viewer — Handoff Doc

Status as of 2026-04-25. This is the **fifth** iteration of the brain visualization (Phase 11 Attempt 5). The first four are documented in `PROGRESS.md` — read this file before changing anything to avoid re-walking the same dead ends.

## What it is now

A **vanilla Three.js** viewer that renders a real cortical brain mesh (GLB) and lights up regions in real time using a **custom emissive shader** driven by TRIBE v2 per-window region activations. Bloom post-processing turns the emissive glow into a believable halo.

- The brain stays still by default. User can drag to rotate (OrbitControls).
- Regions glow in sync with the dashboard's video timeline (`currentTime`).
- Clicking a region pill in the dashboard amplifies that region and dims the others.

## Why NOT React Three Fiber (don't try again without reading this)

The plan was R3F + drei + postprocessing. **It crashes.** Both Turbopack *and* `next dev --webpack` produce:

```
TypeError: Cannot read properties of undefined (reading 'ReactCurrentOwner')
  at $$$reconciler (...node_modules_react-reconciler...)
  at createRenderer (...node_modules_@react-three_fiber...)
```

Root cause: `@react-three/fiber@8` ships `react-reconciler@0.27`, which reads `React.__SECRET_INTERNALS_DO_NOT_USE_OR_YOU_WILL_BE_FIRED.ReactCurrentOwner`. Next 16's React shim does not expose that field in a way the older reconciler can find. Switching to webpack does not fix it. Upgrading to `@react-three/fiber@9` would require React 19, which Next 16 supports but the rest of this app is on React 18.3.1.

The R3F packages (`@react-three/fiber`, `@react-three/drei`, `@react-three/postprocessing`) are still in `package.json` but **unused**. Safe to `npm uninstall` them in a cleanup pass.

## Files

| File | Role |
|------|------|
| `components/BrainViewer3D.tsx` | The viewer. Vanilla Three.js, owns its own canvas + composer + animation loop. |
| `lib/brainVisualization.ts` | Data layer. `getBrainHotspots()` (static centers/colors) + `fillHotspotIntensities()` (per-frame). |
| `lib/brainRegions.ts` | Canonical 7 regions, colors, empirical percentile calibration. |
| `public/models/brain.glb` | The cortical mesh. 162k verts, ~7.6 MB. Generated by `scripts/build_brain_glb.py`. |
| `public/models/JulichBrainAtlas31_*.mz3` | Source meshes — keep these; they're the GLB's only input. |
| `scripts/build_brain_glb.py` | One-off converter: `.mz3` hemispheres → combined `brain.glb`. Re-run if you swap source meshes. |
| `components/ResultsDashboard.tsx` | Parent. Passes `windows`, `currentTime`, `isPlaying`, `focusedRegion`, `onRegionFocus`. **Do not change the prop contract** — the dashboard reads the same data from `features.json`. |

## Data flow (per frame)

```
video.onTimeUpdate
  → ResultsDashboard.setCurrentTime
    → BrainViewer3D props change
      → useEffect mirrors props into stateRef
        → requestAnimationFrame tick reads stateRef.current
          → fillHotspotIntensities(windows, currentTime, focusedRegion, intensities)
            → updates the shared Float32Array uniform
              → shader sums gaussian falloff per hotspot → emissive glow
                → UnrealBloomPass amplifies bright fragments
```

`stateRef` is the bridge between React's render cycle and Three.js's animation loop. The loop never re-runs `useEffect` — it just reads the latest values from the ref every frame.

## The shader (the part that matters)

Injected into `MeshStandardMaterial` via `onBeforeCompile`. Adds 28 hotspots (7 regions × 4 anchors per region) as uniforms.

```glsl
varying vec3 vBrainPos;            // local mesh-space position (MNI mm)
uniform vec3  uCenters[28];        // hotspot positions, MNI mm
uniform vec3  uColors[28];         // per-region color repeated
uniform float uIntensities[28];    // 0..1, refilled every frame
uniform float uFalloffSigma;       // gaussian sigma in mm
uniform float uEmissiveBoost;      // multiplier into totalEmissiveRadiance

vec3 _glow = vec3(0.0);
float _sigma2 = uFalloffSigma * uFalloffSigma;
for (int i = 0; i < 28; i++) {
  vec3 _d = vBrainPos - uCenters[i];
  float _w = exp(-dot(_d, _d) / _sigma2);
  _glow += uColors[i] * uIntensities[i] * _w;
}
totalEmissiveRadiance += _glow * uEmissiveBoost;
```

`vBrainPos` is set in the vertex shader to `position` (mesh-local). Everything in the shader runs in **MNI millimeters**. The `BRAIN_SCALE` group transform shrinks the visual mesh but does NOT affect the shader (since position is local).

## Tunable knobs (top of `components/BrainViewer3D.tsx`)

```ts
const MODEL_URL = "/models/brain.glb";
const FALLOFF_SIGMA = 22;         // glow radius in mm — bigger = bleeds further
const EMISSIVE_BOOST = 0.65;      // overall brightness — careful, bloom amplifies it
const BASE_BRAIN_COLOR = 0x8a7a85; // dim cortex base
const BRAIN_SCALE = 0.013;        // visual size (does NOT affect shader)
```

Bloom (search for `UnrealBloomPass`):

```ts
new UnrealBloomPass(new THREE.Vector2(width, height),
  0.55,  // strength — too high = white blowout
  0.6,   // radius
  0.7);  // threshold — fragments below this don't bloom
```

Camera (search for `PerspectiveCamera`): position `[0, 0.4, 4.4]`, fov `38`. OrbitControls clamp distance to `[2.4, 6.5]`.

Brain orientation (search for `brainGroup.rotation`): `Math.PI / 2, Math.PI, 0` — Euler XYZ. **Don't change unless you understand the MNI-to-three.js axis flip** (see "Axis convention" below).

## Region anchors

Defined in `lib/brainVisualization.ts` (`regionAnchors`). 7 regions × 4 anchors each = 28 hotspots. Coordinates are approximate MNI (`±90 mm`). The `weight` field weakens secondary anchors so the dominant hotspot in each region carries the most glow.

To move a region's glow location, edit the anchor's `x, y, z`. The shader will pick up the change next render — no other file needs to be touched.

To add or remove a region entirely: edit `brainRegionOrder` in `lib/brainRegions.ts` AND update `regionAnchors`. The shader auto-sizes its uniform array from `hotspots.count` (template literal in `BrainViewer3D.tsx`).

## Axis convention (important)

- The `.mz3` source meshes (Julich atlas) and the exported `brain.glb` are in **MNI space**: `+X = right, +Y = anterior (front), +Z = superior (top)`.
- Three.js world is `+X = right, +Y = up, +Z = toward camera`.
- The `brainGroup` rotation `(Math.PI/2, Math.PI, 0)` (Euler XYZ) maps MNI → world so superior is up and anterior faces the camera. It also flips +X so the right hemisphere appears on the LEFT of the screen — this is **standard anatomical convention** (radiological view), not a bug.
- The shader uses local mesh-space (`position`), so anchor coords stay in raw MNI regardless of any group transform. **Do not rotate the anchors** — only the visible group.

## Regenerating `brain.glb`

If you ever swap the source meshes or want to try a different brain model:

```bash
source .venv/bin/activate
python3 scripts/build_brain_glb.py
```

Reads `public/models/JulichBrainAtlas31_LH.mz3` + `RH.mz3`, recenters at origin, writes `public/models/brain.glb`.

If you want to use a **different** GLB entirely (e.g., a Sketchfab download):
1. Drop it at `public/models/brain.glb` (overwrite).
2. Confirm bounds are roughly `±90 mm` so the anchors land in the right regions. If bounds are very different, either edit the anchor coords in `lib/brainVisualization.ts` or apply a one-time bounding-box rescale in `build_brain_glb.py`.
3. If the new model is in glTF Y-up convention (most external GLBs are), the rotation transform may need to change. Test orientation first; debug by setting `BASE_BRAIN_COLOR` to a bright color and reducing `EMISSIVE_BOOST` to 0 so you can clearly see the geometry.

The `scripts/build_brain_glb.py` script avoids scipy by computing vertex normals manually with numpy. Keep it that way; pulling scipy into `.venv` for one function is overkill.

## Common things you'll be asked to tweak

| Ask | What to change |
|-----|----------------|
| "Brain too big/small" | `BRAIN_SCALE` |
| "Glow too bright / blown out" | Lower `EMISSIVE_BOOST`; or raise bloom `threshold`; or lower bloom `strength` |
| "Glow too subtle" | Raise `EMISSIVE_BOOST` first (cheap), then bloom `strength` |
| "Glow blobs too small/large" | `FALLOFF_SIGMA` (in mm) |
| "Brain too dark" | Raise `BASE_BRAIN_COLOR` brightness or directional light intensity |
| "Brain auto-rotates" | It shouldn't anymore — was removed in attempt 5. If it's spinning, look for stray rotation in the `tick` function. |
| "Brain upside down / mirrored" | `brainGroup.rotation.set(...)` — see Axis convention. |
| "Want a different region color" | `brainRegionColors` in `lib/brainRegions.ts` — affects the chart, pills, AND brain glow. |

## Known issues / gotchas

- **Don't add `renderer.outputColorSpace = SRGBColorSpace`** when using `OutputPass`. `OutputPass` already does the sRGB conversion — setting both double-converts and turns the screen into a white blowout.
- **Don't enable `renderer.toneMapping`** when using `OutputPass`. Same reason. Currently set to `NoToneMapping`.
- **WebGL2 fallback**: the component checks `detectWebGL2()` on first render. Browsers without WebGL2 (rare in 2026) get a static panel. The check uses a lazy `useState` initializer, so it only runs client-side; the parent `ResultsDashboard` already wraps the import in `dynamic(..., { ssr: false })`.
- **Linter is strict** about refs during render and `setState` in effects. The pattern in this file (mirror props into `stateRef.current` inside a `useEffect` with no deps array) is the only thing that satisfied both rules.
- **Hot-reload** sometimes leaks WebGL contexts under Turbopack. If the dev page suddenly freezes after many edits, hard-refresh the browser (Cmd+Shift+R).
- **Don't trust ChatGPT** if it tells you to "just use React Three Fiber, it's the standard." It is the standard and it does not work here. Stack matters less than what loads cleanly in this Next 16 / React 18 setup.
